# A field belongs to its Kind

Identity field names are the provider's API names in snake case, identity values are the provider's own strings verbatim, and a field has meaning only inside its Kind: nothing in the system treats two fields in two Kinds as the same because they are spelled alike, identity carries no shared vocabulary across Kinds or providers, and an Annotation scope match object that constrains a field names exactly one Kind. Shared field definitions and a normalised location vocabulary (a global `region` and `zone`) were rejected because their only benefit was letting one scope match object span several Kinds, which a list of match objects does anyway, while they asserted equivalences providers do not keep: the same word can mean different things in two products, and a provider's zone names can be per-account labels. The cost is that a scope spanning Kinds lists one match object per Kind, and cross-provider grouping ("both Frankfurt") lives outside identity as presentation data.
