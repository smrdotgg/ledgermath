# A binary may write to a Service, in an area of its own, never to a Fixture

A binary never changes anything declared, and the rule that binaries never change box state stands for Machines. A Service Target Instance may offer the binary an area of its own, named in the Provisioner's outputs, that no Fixture overlaps and that expires by a bundle constant: for S3, a key prefix with a one-day lifecycle rule. The Variant's Service role block carries an `access` key, `read` or `read_write`, silent meaning `read`, realized in the session policy of the credentials the binary receives and observed by a probe write immediately before the Run, because no AWS API returns a session policy or a `CreateSession` mode after the fact and our own request is never the proof. The Provisioner reads the Fixture's headers back after the Run as it does before, so an unchanged `Last-Modified` proves the Fixture was left alone. Forbidding Service writes was rejected because PUT is a first-class napkin number and a write followed by a read is how a Benchmark attempts a never-read object. The cost is credentials scoped per Run, two probe requests per Run, and a lifecycle rule to keep.

Corrected by Service benchmark trustworthiness (#19), 2026-10-27: on a directory bucket AWS grants access only per bucket, through `CreateSession`, so no credential confines a `read_write` binary to its prefix. There `read` is enforced by a session policy that allows only `ReadOnly` sessions through the `s3express:SessionMode` condition key, and observed by one probe `CreateSession` asking for `ReadWrite`. Under `read_write` a write outside the prefix is caught after the Run instead of prevented, and the catching is made complete on both bucket types. A bucket holds one Station's Fixtures and has exactly two top-level prefixes, `fixture/` and `write/`. A listing after the Run fails it on any key or incomplete upload outside that layout, and the Provisioner deletes what the binary wrote there. A Fixture found changed or missing before a Run is regenerated from its recipe, so the Station loses one Run, not its Series. A second bucket for writes was rejected because on a directory bucket the bucket is the unit AWS scales and grants access by, so splitting reads and writes would rule out Benchmarks that write to the bucket they read. An access point scoped to the prefix was rejected because its scope binds only requests made through it, which would put a second hostname on the measured path.
