# One file per Variant and per Target, discovered by directory, never listed by hand

_Superseded by ADR-0029._

Each Benchmark owns a directory holding its source, its PRD, its declaration in `benchmark.ts`, and one file per Variant under `variants/`, with the Variant's Stations inside its file; each Target is one file under `manifest/targets/` whose path mirrors its slug. The manifest loader discovers these files by reading the directories, and there is no index or barrel file that lists them. Central manifest files were rejected because every pull request on any Benchmark edits the same files and because a Benchmark's declaration then lives far from the code that must agree with it. Barrel files were rejected because two pull requests adding a Variant on the same day both append a line to the same index and conflict, which is the shared edit the one-file-per-item layout exists to remove. Editor help, which is what a barrel otherwise provides, comes from a generated file of Variant names and Target slugs that CI regenerates and checks. The cost is that a Variant's file name must match its name under a fixed rule that CI checks, that a Target slug with optional fields yields a percent-encoded file name, and that a stale generated names file fails CI until regenerated.
