# Nothing of ours but the Artifact sits between the clock and the wire

A Service Benchmark's measured path contains nothing but code pinned by the Artifact hash and the kernel. No provider SDK is linked into an Artifact; the binary speaks HTTP over TLS itself, any request signing finishes before the request's first timestamp, there is no automatic retry anywhere, and every connection opened, reused, or closed is an event in a vocabulary the harness shares across languages. This exists because an SDK makes decisions that move numbers and leave no event: three attempts with backoff on a `503`, a connection pool on its own schedule, signing inside the interval being timed, and in aws-c-s3 a large GET split into parallel ranged parts. Go's `http.Transport` is not exempt, since it resends an idempotent request when a reused idle connection proves dead, so a Go Benchmark dials TLS itself and uses `Request.Write` and `http.ReadResponse` on that connection. An SDK with retries switched off and pooling pinned was rejected because a reviewer cannot verify that configuration by reading, while "no SDK" is a line in a lockfile. The cost is a statically linked TLS library in every HTTP Artifact, a harness-owned HTTPS client for C, and authors who cannot reach for the SDK they know; measuring through SDKs on purpose, to compare software as well as hardware, is parked as a backlog idea outside the map (#33).
