# Nothing of ours decides on the box

A Machine is driven from off the box for the whole of a Visit by a controller, a TypeScript process running as a long-lived task inside the runner VPC, over SSH. The controller runs the capture program and judges the Capture, writes state keys into `/sys` and `/proc`, reads them back as raw text, pushes the Artifact and has the box hash it, launches the binary, holds the SSH session open and silent while it runs, reads everything back, takes the API-side readings, and uploads. The box carries only two static programs, `lm-capture` and `lm-exec`, plus the image's own `sshd`, shell, and tools; it has no internet route, and every judgement, including the pre-flight Capture check and the requirement check, happens off the box. A self-contained on-box runner executing a plan was rejected: written in TypeScript it would put a JavaScript runtime beside the measured process, and written in anything else it would duplicate every observer the registry declares. The proof of concept's user-data script was rejected because it ran blind, with nothing able to judge a Capture before the binaries started. The cost is a controller that must live for hours, which a Lambda cannot, an SSH session open during Runs, made silent by disabling keepalives and keeping the controller in the same VPC so no NAT gateway closes an idle connection, and a box left running if the controller dies, which an independent reaper terminates.

Amended by Service benchmark trustworthiness (#19), 2026-10-26: the box has no internet route unless a Station requires `s3_route: public`, in which case the Provisioner gives the subnet a default route to an internet gateway and the box a public IPv4 address for the Visit, both observed and recorded, and the security group still admits only the controller. A NAT gateway was rejected for that path because its bandwidth scales from 5 to 100 Gbps on a schedule we cannot see.
