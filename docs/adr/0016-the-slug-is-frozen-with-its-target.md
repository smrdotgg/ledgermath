# The slug is frozen with its Target

The identity object is the identity, and the slug is a name derived from it once, when the Target entry merges, and frozen with it: a Kind's renderer may never produce a different slug for an existing identity, an identity schema gains only optional fields whose absence renders nothing and whose absent meaning is fixed in the schema when they are added, Runs store the slug beside the identity object, and a slug is never renamed, not even by the pure-rename commit ADR-0006 allows for parameter keys. Recomputing slugs when the renderer changes was rejected because Runs carry their slugs forever and a recomputed name would stop matching them; renaming was rejected for the same reason. The cost is that a regretted rendering stays, and the slug for a rarely used optional field such as `image` is long.
