How it works

From a cold boot to a figure with a source.

  1. 01

    A machine boots

    One of 5 EC2 machine types in us-east-2 starts fresh, at a scheduled time.

  2. 02

    Benchmarks run

    14 benchmarks run on the freshly booted machine: memory, compute, the operating system, disk and network.

  3. 03

    Evidence is kept

    Each execution is kept as a Run: what the benchmark printed, and what was recorded about the machine.

  4. 04

    Numbers are derived

    A versioned Method turns the Runs of a Series into figures: the 5th, 50th and 95th percentiles across its counted Runs.

  5. 05

    The API serves them

    Static JSON files, each kind with a schema, beside AWS's public On-Demand prices, copied daily.

Behind every figure

A Method, versioned and written down.

Every figure names the Method that made it. These are Method series v1's own definitions, as the API publishes them.

series
The Runs that share a benchmark, params, build, instance type and zone ID.
time_per_repetition
Per Run: for each counted sample (warmup samples left out), sample_ended.t minus sample_started.t, divided by the sample's repetitions; the Run's number is the median of those (the mean of the two middle values when there is an even number of samples).
bytes_per_second
Per Run, where the benchmark observed bytes_per_repetition: bytes_per_repetition × 10^9 / the Run's time per repetition in nanoseconds.
percentiles
5th, 50th and 95th percentiles across the counted Runs of a Series, and of each group, by linear interpolation between closest ranks (R type 7): with n values sorted,h = (n − 1) × p / 100and the percentile isx[⌊h⌋] + (h − ⌊h⌋) × (x[⌊h⌋+1] − x[⌊h⌋]).Each number's percentiles are taken over that number's values, so the bytes-per-second percentiles are not the time percentiles inverted.
