Abstract

LedgerMath boots five AWS machine types in us-east-2 four times a day and runs 14 small benchmarks on each, freshly booted. Every execution is kept as a Run with its evidence, published Methods derive the figures from the counted Runs, and AWS's On-Demand prices are copied daily. This snapshot rests on 6,335 Runs in 187 Series.

For example, m5.large reads memory sequentially at a median of 12.502 615 200 030 773 GB/s over 36 counted Runs (Table 1a; Series a0faf4326dd7).

4Methods

4.1Schedule and machines

Four times a day, at 04:10, 10:10, 16:10 and 22:10 UTC, a machine of each of the 5 types in Table 2 is booted in us-east-2, and each of the 14 benchmarks runs on it while it is freshly booted. The Runs in this snapshot started between 10 November 2026 and 19 November 20261.

4.2Runs, Series and evidence

Every execution of a benchmark is kept as a Run, with its evidence: what the benchmark printed, and what was recorded about the machine. In the Method's words, a Series is “The Runs that share a benchmark, params, build, instance type and zone ID”. This snapshot holds 187 Series and 6,335 Runs: 6,335 counted, 0 failed. A Run either counts or fails, by the rule in §4.5; a failed Run is kept and shown, with its reasons, and is in no figure [4].

4.3Exactness and versions

The API states: “Every number is exactly as the Methods' Derivations hold it.” This page changes units, by moving the decimal point3, and, in Table 1 and Figure 1 only, rounds to four significant digits for reading, which their captions say. Every rounded figure opens to its exact form where it stands; Table S1 and the API keep every digit. On versions: “Version 1 only ever gains fields.”

4.4Figures

The figures are Method series v1's. For each Run it takes the time of one repetition: the median, over the Run's counted samples (warmup samples left out), of

t = (tend − tstart) / r(1)

for a sample of r repetitions; and where the benchmark observes the bytes one repetition moves, B, a rate in bytes a second of

R = B × 109 / tns(2)

Across the counted Runs of a Series it takes the 5th, 50th and 95th percentiles by linear interpolation between closest ranks: with the n values sorted, x0 ≤ … ≤ xn−1,

h = (n − 1) p / 100, Q(p) = x⌊h⌋ + (h − ⌊h⌋)(x⌊h⌋+1 − x⌊h⌋)(3)

Each number's percentiles are taken over that number's own values, so the percentiles of a rate are not those of the time inverted2. The GET from S3 is also summarised request by request, by Method requests v1 [4].

4.5Which Runs count

“A Run counts when its binary exited 0, every stdout line is an event that matches the events schema, and the stream obeys every order rule scripts/check-events.py checks: started first and once (not a --quick stream), finished last and once, samples numbered from 0, each closed by its own sample_ended before the next starts and never ending before it starts, observed keys once, exactly one verified, and as many counted samples as the Run asked for. Any other Run is failed: shown, with the reasons, and in no percentile.”
